# Talapas (University of Oregon HPC): rules for every session

You are running on Talapas, a shared HPC cluster operated by UO Research Advanced Computing Services (RACS). Many researchers share these machines. Most sessions run on a login node, which is shared. Keep work there light, and move anything heavy into a Slurm job, where the user's allocation can be used in full. If the `talapas` skill is available, load it for details.

1. **Login nodes (`login1`, `login2`, ...) are not for computation.** If `SLURM_JOB_ID` is empty and the hostname starts with `login`, don't run anything that takes more than a few minutes, a couple of cores, or a few GB of RAM: no training, analysis, test suites on real data, `make -j$(nproc)`, large conda/pip/R/spack builds or big transfers. Suggest an interactive job (`srun --account=<pirg> --partition=interactive --pty bash`) or a batch script instead. **Inside a Slurm job these limits don't apply:** use the full allocation, sized from `SLURM_CPUS_PER_TASK` / `SLURM_MEM_PER_NODE` rather than `$(nproc)`.
2. **`/home`, `/projects` and `/scratch` are on shared GPFS.** Never run recursive `find`/`grep -r`/`rg`/`du`/`ls -R`/`chmod -R` or broad Glob/Grep searches over `/`, `/gpfs`, `/home`, `/projects`, `/scratch`, or a large data directory. Scope searches to the code you need. Avoid creating huge numbers of small files. Use node-local `/tmp` for heavy temporary I/O inside jobs. Poll `squeue`/`sacct` at most once a minute (`squeue --me`).
3. **Nothing is backed up by RACS, and `/scratch` purges files unused for 90 days.** Confirm with the user before deleting, moving or overwriting data in bulk.
4. **Slurm jobs need `--account=<pirg>` and `--partition`** (there is no default partition), plus realistic `--time`, `--mem` and CPU/GPU requests. Use job arrays instead of looping over `sbatch`. **Ask the user before you submit jobs**, because they are charged to the user's PIRG.
5. **Don't guess Talapas specifics.** Read the official docs at https://wiki.talapas.uoregon.edu (page index: https://wiki.talapas.uoregon.edu/assets/js/search-data.json). Check live state with `sinfo` and `module spider`. Send account, storage and software requests to the RACS Service Desk: https://hpcrcf.atlassian.net/servicedesk/customer/portal/1
